# Project Map

建立供人和后续 coding agent 使用的项目关系地图。结构化索引是可核验的源码快照，HTML 是该索引的查看器；两者不代替当前源码，也不承诺识别全部动态依赖。

## 边界与入口

- 确定用户指定的项目根目录。未指定时使用当前代码仓库；当前目录没有项目、且无法从上下文确定时，询问目标路径。不要自行选择另一个项目。
- 读取适用的 AGENTS.md 和项目说明。默认将产物写入项目的 `.agent-context/`，用户指定位置时使用该位置。分析可以写这些产物，但不修改业务源码、项目规则或配置。
- 检测语言、包管理、构建方式和已有分析工具。优先使用已有编译器、语言服务、AST 工具或项目依赖命令；没有合适工具时使用搜索与源码阅读，标记解析局限。不要仅为建图安装依赖或执行未知初始化脚本。
- 使用 Python 3 标准库辅助脚本。以下 `<skill>` 指本技能目录，`<root>` 指项目目录。路径有空格时加引号。

## 建图流程

1. **建立快照与扫描边界。**

   ```text
   python <skill>/scripts/project_map.py snapshot --root <root> --out <root>/.agent-context/snapshot.json
   ```

   Git 项目列出跟踪文件和未忽略的新增文件；非 Git 项目遍历文件。记录内容哈希和排除规则；默认跳过依赖/构建目录、符号链接、凭证文件和超过 2 MiB 的文件。只从配置样例或读取配置键的代码理解环境变量，不采集密钥值。输出位于项目内的其他目录时，用 `--exclude <相对目录>` 排除该产物目录。

2. **识别模块与入口。** 从构建配置、入口、工作区、路由装配和目录内容确定实际职责。模块划分必须有源码依据，不把每个目录都视为独立模块。列出已阅读文件，保留未阅读范围；大型项目可以先完成有明确覆盖边界的模块概览。

3. **发现并核验关系。** 从入口沿引用读取实现，并反向搜索导出符号的调用方。补充没有 import 联系的 HTTP 接口、消息事件、配置/依赖注入和持久化格式。阅读 [关系协议](references/graph-schema.md) 后写 `analysis.json`。每条边必须有证据位置，所有箭头统一为“依赖方 → 被依赖方”。相同字符串、相似名称或相邻目录只构成候选，不能直接标成已确认。外部消费者与无法解析的动态装配写入未确认范围。

4. **形成可复用的架构摘要。** 在 `analysis.json` 的 `overview` 中描述职责、入口、重要业务链和容易遗漏的跨模块契约。不要复制所有源码或写成泛化架构建议。核验覆盖范围：已阅读的文件不等于该文件的所有关系都已识别。

5. **校验并输出。**

   ```text
   python <skill>/scripts/project_map.py build --snapshot <root>/.agent-context/snapshot.json --analysis <root>/.agent-context/analysis.json --out <root>/.agent-context
   python <skill>/scripts/project_map.py check --map <root>/.agent-context
   ```

   生成 `graph.json`、`architecture.md` 和可直接打开的 `project-map.html`。脚本检查引用、证据文件/行号和快照一致性，不证明关系语义；必须自行核验源码含义。打开 HTML，检查模块和文件视图、点击详情及一项搜索。报告实际读取范围、排除范围和主要未知项，不称为“全部依赖已确认”。

## HTML 查看器质量约束

关系图是查看器的主工作区，必须承担页面的视觉重心；搜索、筛选、统计和详情只作为辅助层，不得用大标题、指标卡或装饰面板与图谱争夺注意力。保持离线单文件、无 CDN 和现有交互协议不变。

- 节点使用统一尺寸、统一内边距和稳定的层级网格；同一依赖深度落在同一列（窄屏时转为同一行），不要按每列高度独立居中造成漂移。
- 连线从明确端口出入，优先使用水平/垂直折线；箭头方向始终是“依赖方 → 被依赖方”，减少无目的交叉。已确认与待核实关系使用稳定、可辨识的线型和颜色。
- 模块、契约、外部边界只使用少量固定语义色；选中节点、选中边和邻域淡化必须清楚，不能靠随机动画或渐变制造层次。
- 桌面布局让图谱占主要宽度和高度；窄屏按“索引 → 图谱 → 详情”顺序堆叠，控件仍可触达。留白、对齐线和文字截断应服务于关系阅读。
- 交付前至少检查桌面和窄屏截图：第一眼能定位图谱中心，节点列/行对齐，箭头不被节点遮挡，详情不会挤压图谱；同时操作模块/文件视图、搜索、节点/边点击、缩放和一跳筛选。

## 查询与刷新

查询前先运行 `check`；代码仓库移动后用 `--root <新路径>`。浏览器页面只显示生成时的快照，不能实时判断源码是否变化。

```text
python <skill>/scripts/project_map.py query --map <root>/.agent-context --node <节点ID或精确文件路径> --direction dependents --depth 1
```

`dependencies` 沿箭头查所依赖的对象；`dependents` 逆向查使用者；`both` 查邻域。返回每条边的类型、确认程度和证据。它是关系查询，不等于本次修改的影响结论。

查询模块 ID 时，范围包含模块及其已记录的文件和契约成员；文件/契约 ID 从该节点起算。接口消费者通常需要经由契约节点走两跳才能到实现。不要因为一跳结果中没有消费者就认定没有跨模块联系。

快照过期时：查看新增、删除和变更文件，重读相关关系；接口实现变化时也检查跨进程消费者。入口、包依赖、路径别名、生成规则或模块布局变化时扩大复核范围。生成新快照后更新分析，重建产物；不要仅更新哈希并沿用旧结论。无法完成复核时说明过期范围。用户只要求建图时，到这里结束。
